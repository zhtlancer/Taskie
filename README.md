## 📖 项目简介

**Taskie (嗒嗒日常)** 是一款专为家庭场景设计的小学生日常作业与学习任务管理系统。

摒弃了传统家校软件臃肿的社交与营销功能，以**孩子自主打卡**为核心，深度针对 **iPad Air 5 横屏视口 (1180 × 820 px)** 进行触控与视觉定制，手机和竖屏 iPad 也有专门的单列布局。集**日常作业打卡**、**趣味激励成长**、**拍照错题本**、**生字生词本与查笔画**于一体，让孩子在正向激励中养成专注自律的好习惯。

## ✨ 核心功能全览

### 1. 🐱 多孩子账号与独立隔离
- **可爱头像选择**：首页直观的 Emoji 萌宠卡片（如 🐱 小明、🐰 小红），一键点击切换；
- **独立 PIN 码保护**：孩子可选配置专属 4 位数字密码，任务进度、积分金币、勋章与错题严格账号数据隔离；
- **独立家长管理入口**：右上角家长控制台设有独立 PIN 码门禁，防止孩子误改配置。

### 2. 📋 每日作业任务看板 (iPad Air 5 横屏优化)
- **大卡片一屏全览**：在 1180 × 820 px 视口下无需滚动即可掌控今日全部作业，触控目标 ≥ 48×48px，防误触；
- **中文字体专属设计**：甄选适宜小学生语文认读的开源名作 **霞鹜文楷 (LXGW WenKai)**，配合规范的 **思源黑体**、童趣 **站酷快乐体** 标题与圆润英文字体 **Nunito**；
- **按孩子分配任务**：每个任务模板可以给全部孩子，也可以只给指定的孩子，适合不同年级；
- **每天自动生成任务**：服务端每天按当天的配置为每个孩子生成并保存任务，孩子当天没打开 App 也一样；当天修改配置会同步到当天，过了零点就固定下来，之后再改模板，或新建开始日在过去的长期任务、课外班，都不会给这天多出要做的事（历史、连续打卡和周完成度一致）；免掉任务仍然可以，比如补设假期或修改长期任务。服务停机期间的日子不会补生成。历史记录里，当天有任务却没有任何记录的日子显示为“未打卡”，不算休息日。
- **临时任务**：老师当天临时布置的作业，家长在总览中给某个孩子的某一天添加，卡片带“临时”标记，和日常任务一样打卡、计入全勤与统计；
- **灵活双模式周期配置**：
  - **模式一（固定星期）**：如周一到周五每日生成“数学口算打卡”；勾选每天则周末也包括；
  - **模式二（每周特定次数）**：如“每周完成 3 次课外阅读 20 页”，卡片动态跟踪周完成进度（`🎯 周目标 3次 · 本周已完成 2/3`）；还可以限定可完成的日子，例如“周末作业，每周 1 次，限周六、周日”。
- **弹性与必做**：每周任务在本周还有余量时显示“🌤️ 今天可选”，不做也不影响当天全勤；当剩余次数等于剩余可做天数时变为“⏰ 今天要做”。
- **放假前的作业可以在假期里补完**：任务模板可勾选此项（如口算、阅读；“学校记事”这类当天要交的不勾）。放假前最后一个上学日的这项任务，截止日期顺延到假期最后一天：周五的到周日，节假日前的到假期结束。截止前每天都出现在看板上，标着“周五的作业 · 周日前完成”，不做不影响当天全勤；到了最后一天变为必做，还没完成就算那天漏做（影响当天全勤和连续打卡）。补完的积分、用时和完成记录都算在原本那一天。上学日为周一到周五、不在孩子假期内的日子，加上家长设置的调休上学日。
- **临时任务的截止日期**：添加临时任务时可选截止日期（如周三布置、周五交的手抄报），截止前每天都可以做，规则同上。
- **调休上学日**：家长在「假期与长期任务」里为孩子设置调休要上学的日子（可一次加给所有孩子），并选择按周几上课：这天按那天的日常任务和课程表来，即使在假期里也照常上学。只能设置今天及以后的日期，已经过去的调休上学日不能删除，以免改写历史记录。新增或删除调休时，过去日期的顺延作业不会因此提前截止，已经过期的也不会重新打开（孩子没打开过的日子同样如此）；截止日仍在今天以后的，照常按新的调休安排计算。
- **每周额外挑战**：家长可为“每周完成若干次”的任务开启“达标后允许额外完成”，默认关闭。达标后孩子仍可在原来允许的星期每天完成一次，在独立的“额外挑战”区记录。额外完成不增加应做次数，也不改变完成率、全勤、连续打卡和写完作业时间；实际用时照常记录。额外每次奖励和每周奖励次数上限都由家长设置（默认 0，不加分）；用尽奖励名额仍可继续记录。进度展示目标与实际完成次数，目标内积分和额外积分分开统计。家长补卡遵守相同规则，撤销按实际奖励扣回并释放奖励名额。修改额外奖励规则只作用于今天起未完成的任务，历史记录和已得积分保留；撤销目标内记录会重新开放目标，已有额外记录不会自动转成目标内或补发积分。
- **家长补卡**：在「数据总览」孩子卡片点「补卡」，选择过去日期，对当天的普通任务（含课外班打卡）逐项补记完成或标记跳过，可选填实际用时；已生成日期保留任务快照；未记录的日期（自动生成上线前或服务停机的日子）按现有模板和课程规则推算（不代表当时配置），请核对后操作，家长操作时才补建普通任务。旧版本已打开但没有普通任务记录的空白日期无法追溯；积分、周目标和完成度归属任务原日期，不计入当天最晚完成时间。可撤销补卡并扣回积分（积分已使用时余额可能为负），补卡和撤销都有操作记录。已跳过的任务须先撤销跳过；字词学习须当天逐项练习，不能补记，漏学的日子可标记跳过（不影响全勤和连续打卡）；长期任务仍在「假期与长期任务」中补记。
- **申请跳过**：某天没有这项任务（如老师没布置），孩子点卡片上的“🙋 今天没有？”并写下理由（必填），家长在总览中同意或拒绝；家长打开孩子看板也可以直接跳过或撤销跳过。跳过的任务不得分，不计入完成度，也不打断全勤和连续打卡（当天任务全部跳过就算休息日）；每周任务跳过一次算用掉一次周目标，长期任务的“每天要记录”也可以跳过当天。申请被拒绝或跳过被撤销后，孩子当天不能再为这项任务申请；孩子直接完成任务会自动撤回申请。
- **任务计时与用时**：家长在任务模板、临时任务或长期任务上勾选“⏱ 记录用时”，可选填预计用时。普通任务通过「学习 / 记录」分次计时，同一天可多次；暂停后继续属于同一次，「结束本次学习」仅保存用时和文字进展，「完成任务」才打卡、结算奖励，也可一键结束计时并完成。多次计时不增加每周完成次数，撤销完成保留实际学习记录。取消分配或调整日历撤掉的任务若已有学习用时，用时照常统计，但这项任务不再出现在看板、历史和周完成度里（重新分配回来时连同用时恢复），待处理的跳过申请同时撤回。假期暂停保留学习记录，之后取消暂停时恢复相应历史任务。跨日用时按实际学习日期统计，任务平均用时和预计用时比较按整项任务累计计算。孩子可补记、更正当天且仍在完成期限内的记录，家长可处理过去日期；未开启计时的任务仍直接完成。已有累计用时保留原值，已知的正在计时片段可继续，不虚构旧分次明细。同一时间只计一项，开始新任务会暂停其他计时；锁屏、刷新或换设备均可继续。孩子端各页面都会显示当前计时条（平板在侧边栏，手机在底部导航上方），可点开对应任务、暂停或继续；暂停后计时条保留，直到这次学习结束、任务完成、长期任务记录进度或计时清零，任务过了可计时的日期也不再显示。家长首页的孩子卡片同样显示计时中或已暂停的任务和用时，点击进入该孩子看板。长期任务仍在每次记录进度时保存本次用时并重新计时。
- **休息倒计时**：计时条（手机底部、平板侧边栏）上点「☕ 休息一下」，可选 5、10、15 分钟。开始休息会先暂停当前学习计时，休息时间不计入学习用时、积分或统计。倒计时可收起到计时条，刷新页面后在同一台设备上继续；到点时这台设备响铃（静音时只弹出提示），并可一键继续原来的计时，也可提前结束休息。休息只保存在当前设备，不同步到其他设备或家长端。

### 3. 🏆 趣味激励系统与交互音效
- **即时正向反馈**：点击打卡触发卡片微动效与金币飘洒动画；
- **连续打卡火焰 (Streak)**：累计连续完成作业天数，跳动火焰动效实时激励；没有安排任务的休息日（如只有工作日任务时的周末、假期中暂停的日子）既不计入也不打断；
- **8 大里程碑勋章墙**：初出茅庐、三连击、一周勇士、月度冠军、小富翁、积分达人、全勤王、优秀学生，达成自动点亮；
- **全勤礼花庆贺**：当天必做任务全部完成时触发全屏彩色纸屑粒子动效；
- **积分兑换商城**：家长设置奖励（如“看 30 分钟动画 = 50 分”），孩子用积分申请兑换，家长确认或拒绝；申请期间积分先冻结，拒绝或撤回后退回；
- **自研 Web Audio 原生音效**：
  - 零外部音频文件依赖，离线秒开，iPadOS 完美支持；
  - 包含金币音 (Coin)、胜利号角 (Fanfare)、勋章叮当音 (Chime)、轻触水滴气泡音；
  - **全局声音开关**：顶部常驻 🔊 / 🔇 开关，状态本地持久化保存。

### 4. 📸 拍照错题本 (触控裁剪 + 自动锐化压缩)
- **原生相机集成**：点击直接调用 iPad 原生后置高清相机拍照或相册选图；
- **多点触控自由裁剪**：基于九宫格辅助线自由拉伸四角框选题目区域，支持 90° 旋转校正；
- **试卷文档增强模式**：
  - **原图模式**：保留真实色彩；
  - **清晰增强（推荐）**：应用拉普拉斯锐化矩阵去除纸张灰暗底色、加黑铅笔与墨水字迹；
  - **黑白文档模式**：自适应阈值二值化（纯白纸张、加黑字迹），便于日后打印重练；
- **服务端 Sharp 高效压缩**：自动校正 EXIF 拍摄方向，将几兆原始照片压缩为 **150KB~250KB WebP** 格式，兼顾画质与轻量存储。

### 5. 📖 生字生词本与 🔍 查笔画系统
- **「🔍 查笔画」**：
  - 输入汉字或词语（最多 8 个字），在超大米字格中动态演示**逐笔笔顺书写动画**（基于 `hanzi-writer`，支持步进播放与重写）；词语可逐字点选查看；
  - 实时解析部首、总笔画数、带声调拼音（词语整词注音，多音字按词读，如“银行”读 yín háng），支持点击「🔊」朗读；
  - 醒目大按钮「⭐ 加入生字生词本」，可同时标记分类，一键存入。
- **「📖 生字生词本」**：
  - 田字格卡片流（霞鹜文楷书法字体展示），词语按字排成多个田字格；
  - **拼音默认遮罩隐藏**，点击卡片「👁️ 拼音」翻牌显露，专为自主认字背诵与默写自测设计；
  - 点开详情卡片支持在 iPad 屏幕上进行**手指描红临摹**练习；
  - 支持按“已掌握 / 学习中”过滤，并可按 **会认读、会写、笔画要改正、易错字** 四个分类筛选；一个字词可以有多个分类；
  - **孩子可以添加分类，去掉分类只有家长可以**（家长在「家长后台 → 孩子账号」点该孩子的「📖 字词本」打开即可）；带分类的字词孩子不能移出，以免纠错标记被删掉；
  - 笔顺数据随应用打包（约 9500 个汉字），不依赖外网 CDN；书法字体仍从 jsDelivr 加载，加载不到时会退回系统字体。

### 6. 📚 长期任务与 🏖️ 节假日、寒暑假
- **长期任务**：需要多天完成的任务，如“读完《西游记》共 200 页”或“口算练习册 50 页，周五前完成”；
  - **两种记录方式**：“读到第几页”（孩子记录读到的位置，系统自动算出今天读了多少）或“今天完成了多少”；也可设为“完成后打勾”；
  - **节奏提示**：有截止日期时显示“还剩 5 天 · 今天建议再做 10 页”，没有截止日期时按最近 7 天的速度估算“预计 11/1 完成”；
  - **积分**：按进度分次得分（如每页 1 分），全部完成再得完成奖励；撤销记录会扣回对应积分；
  - **每天要记录**：可选，开启后成为每天的必做项，当天记录一次进度才算全勤；修改开始或截止日期、关闭此项或删除任务，会免掉不再需要的过去日子的漏记，改回去即可恢复；
- **按孩子设置假期**：为每个孩子设置国庆、寒假、暑假等日期范围，同一孩子的假期不能重叠；也可以补设在过去的日期，免掉那几天暂停任务的漏做，修改或删除即可撤回。新增、修改或删除假期时，“放假前可以补完”的作业不会因此在今天以前截止，已经过期的也不会重新打开；
- **选择假期中继续的任务**：家长勾选哪些日常/每周任务在假期中继续，其余暂停；暂停的任务不生成、不计入完成度、不打断连续打卡；
- **假期任务**：如“寒假作业 共 40 页，每页 2 分”，即日期跟随假期的长期任务；家长可补记或更正进度记录。

### 📚 字词自动学习计划

家长在「孩子账号 → 学习计划」或孩子字词本的「字词学习」进入设置，为认读和书写分别开启自动计划：选择学习日、纳入分类和是否包含已掌握字词，设置每日新学与复习基础目标。字词按条计数；新收录内容自动进入后续清单。到期复习优先，易错字和书写中的笔画纠错内容优先安排；未学内容按收录顺序补入。没有足够内容时不凑数，当天清单生成后固定，配置变更用于下一份清单。

孩子在今日看板点学习任务，逐项先尝试认读或默写，再揭晓答案、播放发音或查看笔顺/临摹，记录「独立完成 / 提示后完成 / 还不熟」。结果来自孩子自评或家长核对，不自动判定读音和书写正确性。完成练习即计入基础进度，不要求全部答对；不自动覆盖字词本的掌握状态或移除分类。

初始复习间隔为独立答对后逐步采用 1、3、7、14、30 天（从实际练习日计算），是可迭代的产品规则，不是适用于所有孩子的固定最优周期。提示后完成不升级、次日再复习；答错回到短间隔。漏学不当作答错，内容继续等待；非学习日不新增必做任务。认读和书写分别记录，同日反复练习不连续升级、不重复领奖；提前巩固答对不跳过既定周期，暴露困难时可缩短复习间隔。

基础目标是最低要求。达标后可自愿继续，每组最多 3 项，依次安排清单外到期复习、新内容和可提前巩固内容；不会增加当天必做数量或改变全勤和连续打卡。页面分别显示「基础目标已完成」和剩余到期数量。基础奖励按每日目标完成一次结算，额外奖励可设置每组积分和每日奖励组数上限（默认关闭），达到奖励上限仍可继续学习。刷新、重复请求和反复练同一条目不重复计分。旧清单保留字词快照，即使原词移出也保留学习记录；最近记录、记忆状态和积分包含在备份中。

### 7. 📅 课程表与课外班
- **学校课程表**：家长在「家长后台 → 课程表」为每个孩子按学期建课程表，自带常见的小学作息（7 节课、课间操、午休），可自行调整时段；点格子填写科目、老师、教室和要带的东西；支持单双周（A/B 周）不同的课；同一孩子的课程表日期不能重叠，新学期可以复制上学期的课程表；假期中不显示学校的课；
- **课外班**：每周固定时间的课，带机构、地点、老师、要带的东西和备注，可以分给一个或几个孩子；家长可以单独给某个孩子的某一次课请假或调到别的时间；可选“上课那天生成打卡任务”，计入全勤和积分，请假或调走的那天不出现，调到的那天出现；
- **按总课次排课**：新增课外班默认按总课次设置（1～520 次），选择每周上课日和开始日期，保存前预览全部课次及最后一次日期；旧课程仍可按结束日期设置。请假保留原课次、不自动延长；调课沿用原课次编号，可调到原结束日期之后。课次表示计划排课；出勤和消课按孩子独立记录，调课不重复计次。
- **出勤与学费**：家长在课外班卡片查看已上、待确认、消课余量、下次上课及预计结课日期，在「出勤与学费」中确认或更正已上课／请假／缺席，并选择本次是否消课。过去未确认的课不自动算作出勤；“待确认”从孩子和课外班都已加入 Taskie、且开始记录出勤（升级到此版本或恢复更早备份的那天）之后算起，更早的课仍可补记；调课是否进入待确认范围按实际上课日期判断，原日期仅用于标识课次。完成上课打卡默认确认出勤并消课，家长更正优先，撤销打卡仅撤销由该打卡产生的出勤，不改变家长独立记录。出勤更正只用于统计，不改变过去的打卡、全勤或积分，只有把今天的课记为请假会取消今天的上课打卡；调课沿用原课次，确认出勤后须先恢复未确认再调课或请假。旧已完成打卡会导入，但无法确认的上课时长仍标为未知。取消分配保留已确认历史，停止未来上课提醒；删除课外班会同时删除本班出勤和学费记录，删除确认中会明确提示，已有作业记录与积分继续保留。两位家长同时编辑同一节课的出勤或同一笔学费时，后保存的一方会被提示“刚被其他设备修改过”，看到最新记录后再决定是否修改；每次更正都会留下修改记录（修改前后的状态或金额与时间），在「出勤与学费」中可查看最近 20 条，并随备份保存。
- **学费统计**：每个孩子可选设置本期总学费，以分保存；有总课次时按比例估算平均每次费用、已消耗和剩余金额，没有总课次时只显示总学费。请假／缺席是否消课由家长确认；已消课超过总课次时提示核对，金额不是机构可退金额。出勤率按已上课与缺席计算，不含请假及未确认；累计上课分钟按保存的课表时长统计，旧时长未知的单独标注。家长首页提供课外班汇总入口。
- **孩子端**：今日看板顶部显示下一节课外班的时间，点开「今天的课」可看今天和明天的课外班（时间、地点、调课或请假状态）、学校课程，以及明天要带的东西；有要带的东西时看板上方会提醒；「课程表」页按周查看，手机上按天切换。

### 📒 作业本（作业记录）
- **按课程记作业**：孩子端「📒 作业本」记下每门课布置的作业，可选课程表里的科目、其他常见科目或孩子的课外班；家长和孩子都可以记，按布置日期分组，可以按课程、是否完成筛选，也可以搜索内容；
- **默认截止日期**：按课程表找到这门课的下一次课，默认截止到下一次课的前一天（作业在家里写）。会跳过孩子的假期，按调休上学日和 A/B 周排课；课外班会跳过请假的课，也会算上调课。布置日期默认是这门课最近一次上课的日子，截止日期可以手动修改；找不到下一次课（没有课程表、学期结束等）时需要自己选；
- **自动生成打卡任务**：截止日期没过时，可以勾选“生成打卡任务”。任务从布置日期开始（最早从今天开始，不改动过去的日子），截止前每天出现在看板上，最后一天必须完成，规则和带截止日期的临时任务一样。卡片上标着“作业”，并显示完整的作业内容。截止日期已过的作业只保存记录，不生成任务。当天已经有同学科的日常任务（如「数学练习册」）时，表单会提示，并默认不勾选，避免重复打卡；
- **孩子记的作业由家长确认**：孩子勾选“请家长生成打卡任务”后，任务要等家长在数据总览里点“生成任务”才会出现；家长也可以点“不需要”。孩子可以修改或删除自己记的、还没有生成任务的作业；
- **按课程统计**：作业本的「📊 按课程统计」按布置日期汇总本周、本月、本学期（课程表的学期日期）或全部的作业：每门课的作业条数，已完成、没按时完成、已跳过、待完成、等家长确认、仅记录各多少条，以及完成率（已完成 ÷（已完成 + 没按时完成），跳过、还没到截止日期和只记录的不计入）。点某门课可以查看这个时间范围内这门课的作业；
- **课程默认积分**：家长在作业本里设置每门课作业任务的默认积分（所有孩子通用，未设置的课默认 10 分），每条作业还可以单独修改；
- **分次做作业**：每份课程作业仍是一项任务，可在作业本或今日看板的「学习 / 记录」中多次学习，同一天也可多次。暂停后继续属于同一次；「结束本次学习」保存用时和可选的文字进展，不标记作业完成。不设页数、题数等数量进度。
- **学习用时与完成**：每次用时单独保存，累计显示，跨零点按家庭时区拆分到实际学习日期，结束记录不重复计入任务总用时。可手动补记；孩子只能更正今天的记录，家长可更正任意过去日期，跨日记录逐日更正。更正用时不改变完成状态或奖励；「作业全部完成」才发放一次积分，撤销完成会扣回积分但保留学习用时。
- **旧累计更正**：家长在普通任务或课程作业的学习记录中点「更正旧累计用时」，填写核实后的分钟数和原因，可减小或归零。更正只影响旧累计，不覆盖分次记录、不改积分或完成状态；保留前后数值、原因和时间，可展开查看更正记录。归零表示旧用时不详：没有分次记录的已完成普通任务在统计中按「缺少用时」处理（可由估算补上），不当作学了 0 分钟；课程作业只统计分次学习，旧累计归零后不再计入统计，删除作业记录后也一样。多设备数值冲突时会拒绝覆盖并显示最新数值，已填写的内容保留，核对后可再次保存。旧累计缺少真实逐日分配，仍按原任务日期显示，不虚构分次或跨日明细。
- **超期作业**：孩子仍可学习并记录用时，申请「作业全部完成」后，由家长在数据总览或作业学习记录中确认；确认前保留原漏做状态。旧版用时保留为旧累计，不虚构分次记录，任务、积分与考核仍归属原任务日期。删除作业记录但保留任务时，已保存的学习用时和完成时间归属仍保留；一起删除任务则删除对应学习记录。
- **课程历史**：删除课外班后，已有作业仍保留独立课程标识，可分别筛选和统计，同名课程也不会混合。升级前已经删除的课外班只能按历史名称归类，旧数据中同名课程已丢失的原始标识无法恢复。
- **修改与删除**：修改作业内容、积分或截止日期时，未完成的任务会同步更新；已经完成、跳过或过了截止日期的任务保持原样。删除作业记录时，可以选择保留任务，或者一起删除任务（已完成的会扣回积分）。

### 8. 📈 周完成度与学习历史
- **本周完成度（截至今天）**：固定星期任务按已到期的日子计算，每周任务只计算本周已无法再补的次数，提前完成的照样计入；没打开 App 的日子也算在内；
- **本周与上周对比**：孩子的历史统计页显示每项任务的本周进度，家长总览显示每个孩子的本周与上周完成度；
- **近 7 天趋势**：每日完成率柱状图，休息日单独标出；
- **长期任务进度曲线**：显示每天累计读到的页数，有截止日期时叠加计划进度参考线。

- **⏱ 用时统计**：家长在「数据总览 → 用时统计」按孩子查看近 7 天、近 30 天或本学期（按课程表的学期日期）：每天按学科分色的作业用时（可切换表格）、各学科占比、每项任务的平均 / 最快 / 最慢用时和与之前的对比、与预计用时相比的超时次数、长期任务的速度（如每页几分钟），以及每天几点写完作业；数据总览的孩子卡片显示今天的作业用时，全部完成后显示几点写完；
  - 只统计打开了“记录用时”的任务，平均值只用有记录的次数；没记录的次数按这项任务自己近 90 天的平均用时估算（至少有 3 次记录才估算），并单独标为“估算”；
  - 孩子的历史统计页只显示自己记录的用时、学科分布和进步（如“口算平均比之前快了 2 分钟”），不显示估算和超时，也不和兄弟姐妹比较。

## 🚀 快速开始

### 方式一：Docker / Docker Compose 部署（强烈推荐，一键运行、零配置）

项目已完整内置多阶段 `Dockerfile` 与 `docker-compose.yml`，支持零环境依赖一键容器化启动。
前端静态资源自动构建并由后端统一托管，数据持久化保存在宿主机 `./data` 目录。

```bash
# 1. 启动容器（后台常驻运行，自动构建前端与后端环境）
docker compose up -d

# 2. 查看运行日志
docker compose logs -f

# 3. 停止容器
docker compose down
```

启动完成后，直接在 iPad 或电脑浏览器中访问：
- **Web 应用与打卡入口**：`http://<服务器局域网IP>:3000`（本机：`http://localhost:3000`）
- **首次设置**：
  1. 第一次打开会显示 6 位**配对码**（设备授权，见下文「设备授权与公网访问」）。在服务器上运行 `docker exec taskie-app node src/cli.js approve-device <配对码> 我的iPad` 授权第一台设备，页面会自动进入应用；
  2. 点击右上角「家长入口」，用初始 PIN `1234` 登录后按提示设置新的家长 PIN，再添加孩子和任务；
  3. 之后的新设备（手机、另一台平板）在「备份与设置 → 设备授权」中输入它显示的配对码即可授权；
- **持久化数据存储**：
  - 数据库文件：宿主机 `./data/data.sqlite`
  - 错题照片目录：宿主机 `./data/uploads/`
  容器更新、销毁与重建过程中，所有作业记录与错题照片均持久保存在宿主机，永不丢失。

> 💡 **已有本地数据迁移至 Docker（可选）**：
> 若此前在本地裸机运行过已有数据，执行以下命令即可平滑迁移进 Docker 挂载卷：
> ```bash
> mkdir -p data
> cp backend/data.sqlite data/data.sqlite 2>/dev/null || true
> cp -r backend/uploads data/ 2>/dev/null || true
> ```

### 方式二：群晖 NAS (Synology) 预构建镜像部署指南（免编译、首选推荐）

群晖 NAS 硬件配置（如赛扬 J4125、Realtek ARM）性能有限，**强烈建议直接使用云端自动预构建好的轻量多架构镜像**，避免在群晖本地进行耗时的 npm 依赖下载与前端编译。

项目已配置 GitHub Actions 自动流水线，每次提交均自动构建多架构镜像并发布到 GitHub Container Registry：
`ghcr.io/zhtlancer/taskie:latest`（同时原生支持 `linux/amd64` 与 `linux/arm64`）。

#### 方案 A：群晖 Container Manager 图形界面直接运行（无需下载源码，仅需 1 个文件）

1. **新建配置目录**：打开 DSM「File Station」，进入 `docker` 共享文件夹，新建 `taskie` 文件夹；
2. **创建项目**：
   - 打开群晖 **Container Manager** ➡️ 点击左侧 **「项目」** ➡️ 点击 **「新增」**；
   - **项目名称**：输入 `taskie`；
   - **路径**：选择刚才创建的 `/docker/taskie` 目录；
   - **来源**：选择「创建 docker-compose.yaml」，并将下方内容粘贴进去：
     ```yaml
     services:
       taskie:
         image: ghcr.io/zhtlancer/taskie:latest
         container_name: taskie-app
     ```

> 📌 **群晖部署小贴士与常见问题**：
> 1. **提示 unauthorized 报错解决**：
>    GitHub Packages 镜像仓库默认将新建镜像设为私有 (Private)。请在 GitHub 仓库主页右侧点击 **Packages** ➡️ 点击 `taskie` ➡️ **Package settings** ➡️ 滚动到底部 **Danger Zone** ➡️ 点击 **Change visibility** 改为 **Public** 即可公开免密拉取；或者在群晖执行 `docker login ghcr.io` 登录具备 `read:packages` 权限的 GitHub Token。
> 2. **运行用户与权限**：容器以普通用户（默认 uid/gid `1000`）运行程序，启动时会自动把 `data` 目录交给该用户，旧版本创建的文件也会一并处理，升级无需手动操作。默认 uid `1000` 在群晖上通常不对应任何账户，文件属主会显示为数字，这不影响使用，并且容器即使被攻破也几乎访问不到 NAS 上的其他文件。若希望属主显示为名称，请在 DSM 中新建一个专用普通账户（如 `taskie`，不加入 administrators 组、不授予其他共享文件夹权限），在 SSH 中执行 `id taskie` 查看 uid/gid，再设置 `PUID`、`PGID`。**不要填写管理员账户**，否则容器被攻破时可能获得该管理员的文件权限。若在 compose 中用 `user:` 指定运行用户，容器不会自动调整权限，日志提示“数据存储目录没有写权限”时，请在 File Station 中为该用户授予 `/docker/taskie` 的读写权限。
> 3. **iPad 桌面独立 App**：在 iPad Safari 中打开 `http://<群晖IP>:3000` ➡️ 点击分享按钮 ➡️ 选择「添加到主屏幕」，即可体验如同原生 App 的沉浸式无边框全屏打卡！
> 4. **外网与 HTTPS 访问（可选）**：如需在外网打卡，可在群晖「控制面板」➡️「登录门户」➡️「高级」➡️「反向代理服务器」中配置一条反向代理规则，将域名与 SSL 证书映射至 `localhost:3000`。

## 💾 数据备份与迁移

### 家长端备份与恢复

登录家长后台，打开「备份与设置」：

- 「立即创建备份」会保存数据库（账号、任务、积分、兑换、假期、长期任务、作业记录与生字生词及其分类等）和一份错题照片清单（文件名、大小、校验值），支持下载 `.taskie.gz` 备份包。备份包不含照片，通常只有几 MB，不会随照片增多而变大。
- 错题照片拍好后不会再改，每张只在 `backups/photos` 中保存一份（Btrfs/XFS 上使用写时复制，不额外占空间），不随每天的备份重复复制；只要当前记录或任一保留的备份还用到，照片就会保留。每张照片的大小和校验值记在缓存里，文件大小、修改时间或文件身份变化时才重新计算，所以日常备份和打开设置页不会重读全部照片，也不会卡住其他操作；恢复和导入照片包时仍按实际内容逐张核对。
- 在「错题照片」中可下载照片包（`.tar`）留存到其他设备：「全部照片」包含当前记录和保留备份用到的所有照片；「只下载新照片」只包含服务器记录中还没有完整导出过的照片。只有照片包完整发送到浏览器后，服务器才把其中的照片记为已导出；下载中断或失败不算。照片包直接由浏览器下载，大小不受限制。
- 导出时逐张核对照片：若某张照片在磁盘上缺失，或内容与清单校验值不一致（且找不到正确副本），会跳过这张照片，照常导出其余照片，并在设置页按「科目 · 日期 · 题目」列出被跳过的照片和原因。被跳过的照片不会记为已导出，修好后（例如上传正确的照片包）下次导出会补上。
- 导出记录保存在服务器本地（`backups/.photo-export.json`），不包含在备份包里。换到新服务器并恢复备份后，导出记录从零开始：第一次「只下载新照片」会包含全部照片。
- 默认每 24 小时自动备份，保留最近 7 份；启动时若没有备份或最近备份已过期，会立即补做。
- 恢复需要当前家长 PIN 和确认勾选。系统在工作线程中解压、检查并准备备份，再保存恢复前快照；数据库恢复失败会回滚数据库和照片目录。照片按备份中的清单从本机保存的照片中取回，并逐张核对校验值。备份、恢复或上传照片包期间，删除错题、删除孩子的请求最多排队 10 秒；超时会提示稍后重试，等待期间断开连接也会取消本次删除，不会在后台继续执行。
- 在新服务器上恢复时，本机没有这些照片：数据照常恢复，「错题照片」会列出缺少的照片，上传当时下载的照片包即可补齐（可上传多个；已存在且校验一致的照片不会被替换，校验不一致时会用照片包中的正确照片修复；无关或没有可信校验信息的照片会被忽略）。保留备份引用、但已从当前错题中删除的照片也可按备份清单校验后补回。旧版本生成的带照片备份仍可直接恢复。
- 恢复完成后所有会话失效，需要重新登录。备份中的账号、PIN 和学习记录会替换当前数据。
- 备份数据（解压后）最大 256 MiB；现在只含数据库，正常使用不会达到。
- 若某张错题照片的文件已在磁盘上丢失，备份仍会完成并保留该错题记录，页面会提示丢失的照片；恢复后这些错题同样没有照片。

Docker 部署的自动备份位于宿主机 `./data/backups`，数据库和照片在 `./data/data.sqlite`、`./data/uploads`。请定期将备份下载到另一台设备，NAS 上的同盘副本无法覆盖磁盘故障。

可用环境变量：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `TIME_ZONE` | `Asia/Shanghai` | 任务日期、周界线及连续打卡使用的家庭时区 |
| `DEFAULT_PARENT_PIN` | `1234` | 全新安装时的初始家长 PIN，首次登录后必须修改 |
| `DEVICE_AUTH` | 开启 | 设备授权门禁；设为 `off` 关闭（仅建议本地开发使用） |
| `AUTHORIZED_TOKENS_FILE` | 数据库所在目录下的 `authorized_tokens` | 已授权设备列表文件 |
| `BACKUP_INTERVAL_HOURS` | `24` | 自动备份间隔；设为 `0` 关闭 |
| `BACKUP_RETENTION` | `7` | 保留的备份份数 |
| `BACKUP_DIR` | 数据库所在目录下的 `backups` | 备份存储目录 |
| `JWT_SECRET` | 自动生成并保存到数据库 | 可选的自定义签名密钥；勿使用示例中的固定密钥 |
| `PUID` / `PGID` | `1000` / `1000` | Docker 中运行程序的用户与用户组，启动时自动接管数据目录；如需修改，请使用专用普通账户，不要使用管理员账户 |

升级会自动迁移旧数据库并保留账号、任务与历史记录。v23 起，课程作业的「几点写完作业」按实际完成的晚上统计，旧版已完成课程作业也采用此口径，所以升级后历史完成晚间与平均时间可能变化；凌晨 04:00 前计入前一晚，04:00 起计入当天。任务、积分、考核所属日不变，家长补卡不进入晚间完成统计。学习用时按家庭时区午夜拆分，与晚间完成统计的 04:00 分界不同；未完成任务已保存的学习时间也计入实际学习日。v24 新增旧累计更正记录，随备份保存和恢复；更早的备份可正常升级，恢复旧备份会以该备份的数据为准。v25 独立保存课程作业来源，删除作业记录、撤销或再次完成后，旧累计归零的统计口径仍保持一致。升级时根据现存作业关联或可靠的完成归属标记回填；升级前已删除作业且没有这类证据的旧任务，无法可靠还原其来源。v26 为每个孩子记录最近一次使用的计时，供暂停后的计时条显示和继续；升级时正在计时的会被记录，升级前已暂停的计时在下次开始后才会出现在计时条上。旧版只保存在前端演示库中的周频次设置无法从服务器恢复，需要在升级后重新设置。

### 升级与回退演练（NAS）

数据目录检查（`npm run test:docker-data`，需要 Docker）会用真实镜像和宿主机绑定目录确认：已有目录交给 `PUID:PGID`、替换容器后记录和照片仍在、只读或无写权限的目录在启动时直接给出“数据目录不可写”的提示、已被新版本升级过的数据库拒绝由旧版本打开。

建议每次升级按以下步骤：

1. 在「备份与设置」下载一份最新备份，并在停服后复制整个 `./data` 目录（含 `data.sqlite`、`uploads/`、`backups/` 和 `authorized_tokens`）。
2. 在 `docker-compose.nas.yml` 同目录的 `.env` 中用 `TASKIE_TAG=sha-xxxxxxx` 固定镜像版本（标签见 GitHub Packages 发布记录），记下当前使用的标签。
3. 修改 `TASKIE_TAG` 为新版本后重建容器，打开孩子看板、作业本和「备份与设置」确认数据完整。
4. 需要回退时：停掉容器，用第 1 步复制的 `./data` 整体替换当前目录，再把 `TASKIE_TAG` 改回原标签。新版本可能已升级数据库结构，旧版本会拒绝打开升级过的数据库并提示原因，因此回退必须连同升级前的数据目录一起恢复。
5. 恢复备份时若遇到断电或容器被强制停止，下次启动会根据恢复日志自动收尾：数据库已写入则保留恢复后的照片，否则放回恢复前的照片，保证记录和照片来自同一份数据。

### 设备授权与公网访问

所有页面、接口和错题照片都要求设备先获得授权，局域网访问也不例外，便于通过 frp 等方式在外使用：

- **配对**：未授权的浏览器只能看到一个配对页面，显示 6 位配对码（10 分钟内有效，过期可刷新）。家长在已授权设备的「备份与设置 → 设备授权」中输入配对码并填写设备名称，新设备会自动进入应用，之后长期有效。后台不会列出待批准的请求，只有知道新设备屏幕上配对码的人才能授权它。
- **第一台设备**：在服务器上运行 `docker exec taskie-app node src/cli.js approve-device <配对码> [设备名称]`；`list-devices` 列出已授权设备，`revoke-device <设备编号>` 撤销。
- **授权文件**：已授权设备保存在数据目录的 `authorized_tokens` 文件中，每行为“令牌 SHA-256、授权时间、设备名称”，只保存哈希、不保存令牌本身；可手动编辑，删除某一行即撤销该设备，无需重启。该文件不在应用备份中，迁移到新服务器后需要重新配对或一并复制。
- **授权记录**：新设备请求配对（配对码、来源 IP、浏览器）、授权、配对码输错、错误过多被暂停、撤销，以及通过服务器命令或手动编辑授权文件做的改动，都会记在「设备授权 → 最近的授权记录」里，并以 `设备授权：…` 开头写入容器日志（可在 Container Manager 的日志中查看），例如：`设备授权：授权了设备「妈妈的 iPhone」（在「客厅 iPad」上操作）`。来源 IP 依次显示 `X-Forwarded-For` 和直接连接的地址，可能被伪造，仅供参考；令牌不会出现在记录和日志中。服务器命令的操作会在服务端下一次收到请求时写入容器日志。记录保留最近 500 条，配对请求另外保留最近 300 条。
- **设备令牌**：保存在 `HttpOnly`、`SameSite=Lax` 的 Cookie 中，网页脚本无法读取；应用不允许跨域访问，其他网站无法借用已授权设备读取数据。在 iPhone 上，“添加到主屏幕”的应用与 Safari 存储相互独立，需要分别配对一次。
- **公网访问必须使用 HTTPS**：frp 默认转发明文 HTTP，令牌、PIN 和登录会话都会以明文在公网传输。请在 frps 的 HTTPS vhost 配置证书，或在公网服务器上用 Caddy/Nginx 终止 TLS，并转发 `X-Forwarded-Proto: https` 请求头，这样设备 Cookie 会带上 `Secure`。
- **不要按来源 IP 放行**：经过 frp 后所有请求都来自 frpc 所在主机，无法区分局域网与公网，因此本应用不做任何基于 IP 的免授权。

### 登录与网络行为

API 需要有效会话：家长管理账号、模板和备份，孩子仅可访问自己的记录与照片。会话有效期为 12 小时，PIN 登录连续失败 10 次后限制 15 分钟。首次使用默认家长 PIN（`1234`，或 `DEFAULT_PARENT_PIN` 设置的值）登录后，必须先设置新 PIN 才能使用家长后台；新 PIN 不能与默认 PIN 相同。修改家长 PIN 会让已有会话失效；家长设置、修改或清除某个孩子的 PIN，只会让这个孩子已登录的设备退出，其他孩子和家长不受影响。

断网时操作会提示失败，不会切换到本地数据。浏览器已有的旧版登录状态需要重新登录。

### 原生运行时手动备份

以下命令用于原生 Node 部署，请先停止服务；运行中优先使用家长端快照备份。

- **数据库**：所有账号、任务、积分与生字生词均存储在单一文件 `backend/data.sqlite` 中；
- **图片**：所有错题照片均保存在 `backend/uploads/` 目录中；
- **一键全量备份**：
  ```bash
  tar -czvf taskie_backup_$(date +%Y%m%d).tar.gz backend/data.sqlite backend/uploads/
  ```
